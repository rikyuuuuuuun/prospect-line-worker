# Aチーム LINE返信アシスタント（2026-10-29 監査修正版）

## 所有者の指示と範囲

- Aチーム7会場のみ。既存LINE署名検証→Queue→GASを維持し、別のDurable Objectへ受信を複製する。
- 過去のAチーム返信は、所有者の申告により原則本人。スタッフ作成と分かるものは区別する。「担当者表示」と「執筆者の確定」は別。
- OpenAI APIを利用する。Notion PT-17の旧ローカルAI限定方針より、今回の所有者の指定を優先する。Notionは未変更。
- 欠席の振替なし。体験後の未入会者への営業フォローなし。体験当日や相手から依頼された入会手続きの案内は別用途とする。
- 原文と個人識別情報は30日で消去し、本人が承認した匿名事例は保持する。既存のSheets/GAS原本には書き込まない。
- このアシスタントにPush API・Reply API・送信機能はない。旧`/assistant/api/send`は404。既存LIFFの申込控え機能は変更しない。

## 返信案の流れ

1. 新着受信または手動追加。WebhookイベントIDで重複抑止。
2. 雨天開催、持ち物、欠席、体験受付等の既知の用件は、原文を送らず固定語彙の要約をローカルで作る。氏名・URL・任意の文字列は要約へ転記しない。複数の質問対象と「明日」等の時期を残す。
3. 用件が判別できない相談は`privacy_review`で停止。管理者が匿名化候補を確認・編集して保存する。匿名化は完全ではなく、ラベルのない氏名・診断名等は人の確認が必要。詳細な条件や具体的な希望日は、必要に応じて確認済み匿名本文へ補う。
4. 自動生成と手動生成は同じ`generate()`内で会員正本・日程正本を取得する。会話は会場とLINE IDで分離し、過去の本文は確認済み匿名文だけを渡す。
5. 同会場・本人・承認済み匿名事例を類似検索する。分類の一致だけに限定せず、文章類似度でも候補を取得する。定型文は承認と用途が合うものだけを入力する。
6. Responses APIで案を作る。元の案を保存し、検査が指摘した場合は`draft_review`で表示する。一律の汎用文への置換はしない。
7. コピー前に、振替なし・営業フォローなし・事実確認をチェックする。編集後はチェックを解除する。検出した方針違反や未入力の空欄は修正が必要。数値等は単位別に検査し、日付の数字を金額・時間の根拠にしない。
8. サーバーで版と参照元を確認してからクリップボードへ渡す。後から届いたメッセージがあれば、その本文を表示し、個別IDの確認を求める。画像等はLINE管理画面で確認する。
9. LINE公式管理画面から手動送信した後、最終本文・日時・執筆者を申告する。コピーだけでは送信済みにならない。案が無効化されていても、その版を指定して実送信の記録を残せる。元の受信より前の日時は受け付けない（分入力の端数だけ許容）。
10. 最終文は未承認の学習候補にする。本人の同会場・同分類の修正が繰り返された場合に改善候補を提案する。スタッフ・不明の文は本人文体へ自動昇格しない。

自動要約には細部が欠ける場合がある。任意の自然文を完全に理解・匿名化する仕組みではない。元の問い合わせと案の照合を必須とし、不明な点は匿名本文を確認して再生成する。希望クラスと、文脈上明らかな退会希望の月末を固定語彙の要約へ残す。少数の匿名事例による実API評価は実施済みで、本人による文体の比較確認と追加履歴での評価が残る。

本人の承認済み事例から、敬語・句読点・改行・挨拶・安全な定型表現・絵文字の使い方を明示的な文体ガイドへ変換する。会場や手続きに関する過去の事実は文体と区別する。欠席・体調不良等に一律に絵文字を付けない。営業フォロー等の理由でモデルが生成を見合わせた場合も、理由を確認事項として保存し、空の返信のコピーを停止する。

## 履歴・テンプレート

- CSVはペア形式、または会話ID・送受信方向・日時を明示したメッセージ形式。UTF-8/Shift_JIS、引用符内改行に対応。実CSVの列を取得前に決めつけない。
- `authorColumn`と任意の`authorValues`対応表で、執筆者を行ごとに指定できる。指定列がある場合はファイル全体の初期値より優先する。管理画面の初期値は所有者の指示に沿って「本人（Aチームの原則・変更可）」。
- 1回200件/500KB、事例上限2000件。未承認・除外・スタッフ・執筆者不明は検索に使わない。
- 日付の不一致、年度固有の記述、方針違反候補を隔離・警告する。代替日案内と誤記は自動では確定できない。事例を確認・修正して承認する。
- 候補の空欄化は漢数字の金額、時刻、第2土曜等も扱う。会場固有の案内は現在の正式案内で確認する。
- テンプレート承認時にも方針・個人情報・残った日時や料金の検査を行う。入会フォーム案内には`same_day_procedure`の用途確認が必要。生成時も「当日または依頼された手続き案内」の確認がある場合だけ入力する。
- モデルが利用したと申告するIDと、入力へ含めた全IDを別に保存する。停止・変更時の無効化は全入力IDと内容の版を基準にする。
- 承認要求が失敗した場合は関連案を無効化しない。旧形式の案はコピー時に停止し、更新を求める。実送信の記録は残せる。

## 正本と鮮度

`ASSISTANT_MASTER_SHEET_ID`で指定した正本を、Google Sheets読取専用スコープで取得する。IDを新規モジュールへ固定しない。列のヘッダーを毎回検証し、変更時は取得失敗として扱う。

- `17_LINE会員連携`: B（LINE ID）、D:E（人物・会員ID）、K:N（在籍・チーム・会場・連携状態）、Q（元ルート）。氏名・生年月日・自由記述の連携根拠は取得しない。
- `14_LINE体験受付`: C:F（受信・更新日時・チーム・会場）、I（LINE ID）、N:P（抽出状態・体験日・クラス）、X（反映状態）。子どもの氏名や会話原文は取得しない。
- 兄弟等の別人物IDの連携は家庭として集約する。重複・人物不明はunknown。現在、実際の連携済み行のデータによる受入は未確認。
- 古い受付、過去の体験、対象外は現在の予約根拠にしない。取消・キャンセル待ちの明示状態を分離する。反映済みを申込完了とは扱わない。現行の観測列からは`applied`を返さず、正本での完了証拠の対応付けが残る。
- 日程は既存`AvailabilitySnapshot`を再利用。`sourceSyncAt`は実際のrevision、`sourceUpdatedAt`は内容更新時刻。取得時刻で塗り替えない。保存経過分数も表示する。
- 日程の許容経過は既定12時間。`ASSISTANT_AVAILABILITY_MAX_AGE_MS`は1分〜12時間に限定。古い、空、取得失敗、未来の不正時刻は未確認扱い。過去の日付は候補から外す。

## 認証・保存・費用

- 32文字以上のランダムな管理者Bearerトークン。同一Origin、CSP、no-store、iframe禁止。ブラウザはトークンをメモリ内だけに保持する。共通トークンは個々の執筆者本人を証明しない。執筆者は登録者の申告として表示する。
- 本番のOpenAI・Googleサービスアカウント・管理者用の秘密はCloudflare Secrets。ローカル評価キーは、所有者が承認したGit管理外のenvファイルに保存する。GitHubへ実履歴や秘密を入れない。
- 受信箱、未承認事例、モデル原案、最終返信、匿名本文確認の元情報は30日で原文・識別情報を消去する。承認済み匿名事例を残し、期限経過時に元の出典情報も一般化する。個人別の上限・コピー確認用ハッシュも期限で削除する。元Sheets/GASや別途の手動バックアップはこの処理の対象外。
- 保存期限処理は受信・一覧・生成とアラームで行い、次の期限へ向けて再予約する。履歴だけを取り込んだ場合も予約する。受信・生成のフラグを無効にしても期限処理は継続する。Worker自体が実行できない停止・障害時に厳密な時刻で消去することは保証せず、再開時に期限分を処理する。
- Responses API: `store:false`、構造化出力、45秒期限、最大2048出力トークン、Standard指定。`store:false`は提供者側のすべての保持をゼロにする設定ではない。[公式データ制御](https://developers.openai.com/api/docs/guides/your-data)
- API初期値は停止。キー、モデル、月間回数・トークン・ドル見積上限が必要。対応モデルは2026-10-29確認の`gpt-6.1-sol`/`gpt-6.1-terra`/`gpt-6-luna`。料金表の更新はコードでレビューする。[公式料金](https://developers.openai.com/api/docs/pricing)
- 日本時間の月ごとに1つのDOで同期的に上限を予約する。実使用が確定すれば予約を精算し、不明の失敗は予約を保持する。ドル値は固定したStandard単価での保守的な見積上限。モデル料金変更、他アプリ・組織全体の請求を保証しない。OpenAI側のプロジェクト上限も別途設定する。
- 自動生成は1相手・1会場につき既定1日3回。管理者による手動生成は月間上限の範囲内。自動購入・自動チャージ・盲目的なAPI再試行は行わない。
- 管理画面は対応中を先に100件ずつ表示する。編集中の返信は画面内更新で保持し、ページを閉じる際には未保存の確認を行う。ブラウザを閉じた後の編集内容は保存されない。

## 本番へ進む前に残る作業

1. 公開GitHub保存は所有者承認により完了し、ドラフトPR #22で管理。main統合・本番配備は未承認。公開mainには旧送信経路が残るため、送信トークンの追加や旧機能の有効化をしない。
2. 所有者による実事例・テンプレートの内容承認と、他会場・不足分類の履歴追加。
3. 本番のOpenAIキー・残高・モデル・料金上限を設定する。ローカル評価用のキーは所有者が作成先と保存先を承認し、標準設定フローで登録済み。本番への登録とは別。値をチャットに貼らない。
4. `ASSISTANT_GOOGLE_SERVICE_ACCOUNT`、`ASSISTANT_MASTER_SHEET_ID`、`ASSISTANT_ADMIN_TOKEN`を設定。新しく権限を広げる場合は別途承認。
5. 生きた人物連携、申込完了・取消・キャンセル待ちの正本で、実際の行との対応付けを受け入れる。会費・活動予定の情報源を追加する場合も正本を指定する。
6. 匿名の実返信3件と確認シナリオを使い、初回12要求・調整後12要求・最終4要求の実API評価を実施済み。本人による比較確認と、他分類・他会場の履歴を増やした検証が必要。同じ問題での調整後の結果を独立した再現率とは扱わない。
7. 承認後、最初はAPI停止で実受信→既存GASと受信箱の双方を確認する。他チーム非回帰・手動送信後の記録まで確認して段階的に有効化する。

停止は`ASSISTANT_API_ENABLED=false`（API生成停止）または`ASSISTANT_ENABLED=false`（新機能停止）。既存Queue/GASは維持する。本番変更前に直前のCloudflare版を記録する。

## 実API評価の再実行

`src/assistant-model.js`を運用と評価で共有し、同じResponses API入力を使う。評価用の匿名データ・結果・APIキーは公開リポジトリの外へ保存する。評価専用の参照コピーを使っても、運用データを承認済みに変更しない。

```
node scripts/evaluate-assistant.mjs --plan ../evaluation/plan.anonymous.json --output ../evaluation/results.json
```

既定はAPIを呼ばない事前確認。`OPENAI_API_KEY`をプロセス環境へ安全に渡し、`--execute`を付けると実行する。1評価ファイルあたり最大12件・設定上限は最大1ドル。複数回に分ける場合は、前回までの実使用を差し引いて次回の上限を設定する。呼出し前に費用を予約してチェックポイントを保存し、実使用量で精算する。失敗や使用量不明の要求は自動再試行しない。同じ結果ファイルの完了済み要求は再実行しない。

対象の実返信を参考入力から除く比較と、参考事例なしの対照を分ける。文字数・感嘆符・絵文字・編集距離は参考値であり、文体の正解率ではない。過去の退会処理完了や物品発見を現在の事実として再現した場合は不合格とする。本人による比較確認が必要。

実データの読取では、`14_LINE体験受付`の会場は`01_さいたま芝川`等の番号付きだった。既知のAチーム正規名と対応する番号付き名のみを照合し、別の会場を混同しない。日程・受付状態は活動カレンダー、運用入力、配信中のSnapshotを照合する。Google Drive経由の確認と、Workerサービスアカウントの実接続は別の検証として記録する。
